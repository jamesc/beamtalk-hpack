# hpack

HPACK header compression for HTTP/2 (RFC 7541), a pure-Beamtalk port of
[hpax](https://github.com/elixir-mint/hpax) 1.0.4.

```beamtalk
t := HPACK newTable: 4096 huffman: #always
{io, enc} := HPACK encode: #({#store, ":method", "GET"}) table: t
wire := Binary fromIolist: io
{#ok, headers, dec} := HPACK decode: wire table: (HPACK newTable: 4096)
```

## Classes

| Class | Port of | Role |
|-------|---------|------|
| `HPACK` | `HPAX` | Encode/decode contexts (immutable `HPACKTable` values, one per direction) |
| `HPACKTable` | `HPAX.Table` | Static table (RFC 7541 Appendix A) + dynamic table, eviction, resizes |
| `HPACKTypes` | `HPAX.Types` | Prefixed integers (§5.1) and string literals (§5.2) |
| `HPACKHuffman` | `HPAX.Huffman` | Huffman code (Appendix B), tables built once per VM into `persistent_term` |

Every class is `typed`; a type warning fails the build.

## Public API

```beamtalk
// Tables
HPACK newTable: 4096                        // never-Huffman table
HPACK newTable: 4096 huffman: #always       // #always | #never, else raises
HPACK resize: t newMax: 256                 // protocol-maximum resize (hpax resize/2)

// Encoding: headers are {action, name, value} triples, action one of
// #store, #store_name, #no_store, #never_store. Answers {iodata, table}.
HPACK encode: headers table: t
HPACK encode: #store headers: pairs table: t   // one action for all

// Decoding: answers {#ok, headers, table} or {#error, reason} with hpax's
// reasons (#protocol_error, {#index_not_found, index},
// #bad_integer_encoding, #bad_binary_encoding,
// {#protocol_error, #invalid_huffman_encoding}).
HPACK decode: wire table: t
```

Lower layers (`HPACKTypes encodeInteger:prefix:flags:`,
`HPACKTable lookupByIndex:` / `lookupByHeader:value:`,
`HPACKHuffman encode:` / `decode:`) are public and documented with
`## Arguments` / `## Examples` in source.

## Building and testing

```bash
just build   # beamtalk build
just test    # beamtalk test
just ci      # fmt + lint + build + test, as CI runs it
```

Tests: 58 BUnit tests — the 37 hpax cases, RFC 7541 Appendix C vectors
(C.2–C.6), seeded round-trip loops (no StreamData; `Random` with an
`(Erlang rand) seed:`), plus a 40-block hpax-differential fixture
(`test/fixtures/hpax_vectors.txt`, generated by `bench/gen_vectors.exs`
against hpax 1.0.4).

## Benchmark vs hpax

`bench/bench.exs` times hpax 1.0.4 encoding + decoding a 6-header request
block (`:method/:scheme/:path/:authority`, `cache-control: no-cache`,
`custom-key: custom-value`), always-Huffman, fresh tables per op, 2000
iterations. The Beamtalk side timed the same shape (2-header block) over
2000 iterations. Same machine.

| Op (per iteration) | hpax | hpack | Ratio |
|--------------------|------|-------|-------|
| encode + decode round-trip | 3.88µs | ~126µs | ~32x |
| HPACK encode (always-Huffman) | — | ~91µs | — |
| HPACK decode | — | ~35µs | — |
| Huffman encode (`www.example.com`) | — | ~11µs | — |
| Huffman decode | — | ~13µs | — |

Notes:

- This is a correctness-first port; the gap is dominated by per-header
  table scans (61 static entries as tuples) and byte-list handling, not
  the Huffman code itself.
- Huffman decode was ~108µs/op with hpax's bit-walk shape; the
  nibble-driven DFA in `persistent_term` brought it to ~13µs/op (~8x).
- `persistent_term` lookups measured ~0.05µs — the build-once design pays
  for itself immediately.
